# 发布程序和共享资料

公开只读网站的构建、验证与发布见 [网页说明](web.md)。网页或共享资料更新推送主分支后自动部署网站；桌面安装包仅通过版本标签或手动工作流构建，普通主分支推送不会打包。

程序安装包与公共数据分别发布。维护者审核公共基础资料，其他人订阅并在预览后更新；修改建议通过仓库 Issues 提交。个人档案不通过代码仓库同步。

## 首次公开仓库

在 GitHub Desktop 中选择本项目目录，检查 Changes 中即将提交的文件。应包含源代码、依赖锁定文件、构建资源、公开文档、测试源码和工作流。不得包含个人数据库、图片目录、原始测评、备份、导出包、缓存、测试截图或嵌套仓库。

本项目的 `.gitignore` 排除了这些常见目录。忽略规则不会自动移除已经提交过的文件，因此首次发布及后续推送前仍需检查变更和历史。正式安装包作为 Releases 附件上传，不放进源代码历史。

确认提交内容后使用 GitHub Desktop 的 Publish repository 发布为公开仓库。仓库描述可填写“全国健身房地图、器械档案与可订阅公共资料”。发布后在未登录浏览器中检查仓库、说明和附件能否访问。搜索引擎和 GitHub 搜索的收录存在延迟，应同时提供仓库直达链接。

## 发布软件版本

1. 更新 `package.json` 和依赖锁定文件中的版本号，完成适当测试与桌面验证。在 GitHub Desktop 提交并推送代码。
2. 在仓库 Actions 中手动运行 **Build Windows release draft**，或推送 `v` 加版本号的标签，例如 `v1.4.0`。标签必须与包版本一致。
3. 工作流在 Windows 安装依赖、运行单元测试并构建安装包，检查下面四个附件齐全后创建或更新同版本发布草稿。已经公开的同版本发布不会被工作流覆盖。
4. 在 Releases 中检查草稿的版本、说明、附件，下载并验证安装包。自动构建不替代实际安装和桌面功能验证。
5. 检查通过后公开该草稿。用户从 Releases 下载，或使用应用的数据与设置页面检查软件更新。

必要附件：`NationalGymMap-Setup.exe`、`NationalGymMap-Setup.exe.blockmap`、`latest.yml`、`checksums.txt`。不要手动更改安装包后继续使用旧的更新清单或校验文件。

工作流使用 GitHub 临时令牌创建发布，不需要把个人令牌写入仓库。首次使用可能需要在仓库设置中允许 Actions 工作流写入内容。安装器组件由构建脚本下载并核对校验值，网络失败时应修复构建后重试，不跳过校验。

## 发布共享资料

共享数据不是个人完整备份。维护者从应用的共享导出入口生成公共快照，先审查预览，仅选择可公开的场馆基础资料、器械、关联和有分享权限的图片。默认不应公开到访状态、私人备注、原始测评、个人设置和导入原文件。

照片中的人物、联系方式等也可能包含私人信息；字段过滤无法判断图片内容，维护者必须逐张确认分享权限和内容。没有授权的官网图片不应随公共库再分发，可保留公开产品页来源供核验。

审查后按应用导出格式发布快照文件，并提供稳定、公开可读的订阅地址。不要把整个数据根目录或备份压缩包当作共享快照。维护者修订资料后发布新版快照，订阅者检查更新、查看新增与修改内容，再应用到本地。个人状态保持本地；遇到冲突以应用预览规则为准，不直接覆盖完整数据库。

应用入口为“数据与设置 → 共享资料库”。默认订阅地址为 `https://raw.githubusercontent.com/player9826/national-gym-map/main/shared/manifest.json`；检查共享数据后预览，再确认同步。维护者选择“导出共享库”，导出到本仓库的 `shared` 目录，通过 GitHub Desktop 审阅并提交、推送该目录。该目录的 `manifest.json` 保留发布者标识，不应手工替换标识或单独更新清单；资料和图片应作为同一提交推送。

清单包含资料及图片的散列校验值；接收者确认前完成校验，确认后先备份再合并。首次同步为共享记录建立本地标识映射；之后只更新未被本地修改的公共字段，发生冲突则保留本地内容。共享库移除记录不会删除接收者本地档案。个人打卡、私人备注和原始测评不参与共享更新。

## 提交资料修正

在仓库 Issues 选择“场馆或器械资料修改建议”，提供场馆城市及名称、器械名称、当前资料、建议修改、核实日期和公开来源。不要附上个人数据库或完整备份。维护者核实后更新共享库，并在讨论中说明采用情况。

## 发布后验收

使用未登录会话打开公开仓库和 Releases，下载安装包并校验；在隔离的空白档案订阅共享库，确认预览和应用后能看到场馆、器械、关联及获准分享图片。再发布一份小修订，用保留了个人到访状态和备注的档案更新，确认公开资料更新而个人数据保留。

软件更新也须在隔离环境确认版本检测、下载和备份安装流程。任何没有实际完成的步骤，应在发布说明中记录为待验证。

品牌标识共享从 1.5.0 起支持：发布包含自定义品牌标识的共享快照前，接收端应升级至 1.5.0 或更新版本。内置品牌标识随程序提供，旧共享库无需修改即可继续订阅。

历史 1.5.2 经维护者授权公开发布。2026-09-22 起工作流取消该历史版本的自动公开特例，后续桌面发布统一先生成草稿。
